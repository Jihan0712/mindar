# Architecture

## Stack

- **App:** React 19 + TypeScript, built with Vite. Routes in `src/App.tsx`; the 3D/AR pages are lazy-loaded (three.js and the tracker are large).
- **3D:** three.js (r186). `THREE.Timer` for frame timing; `PCFShadowMap` (soft shadow map type was removed from three).
- **AR tracking:** MindAR 1.2.5 image tracking, its core only (`mind-ar/dist/mindar-image.prod.js`: `Controller`, `Compiler`), typed in `src/types/mind-ar.d.ts`.
- **Validation:** zod for the scene format.
- **Hosting:** Cloudflare Workers with static assets (separate INRL2 account), configured in `wrangler.jsonc`; auto-deploys from GitHub `main`.

## Scene format (`src/scene/schema.ts`)

What InStudio saves and every viewer reads. Version 1:

- `objects` (max **6**, `MAX_OBJECTS`): `model` (glTF `src`, `height`, optional `animation`), `image` (`src`, `width`, `frame`), `video` (`src`, `width`, `style: screen | flat`, `loop`), image and video also take `display` (`screen` / `floating` / `marker`) and `screen` (`frame` / `chrome` / `phone` / `tablet` / `flat-tv` / `laptop` / `tv` / `polaroid`); videos have `sound` (one per scene in InStudio) and `gif`; media keep their `aspect`; `src` may be `media:<id>` (the person's own photo/video: on the phone in IndexedDB until uploaded, then at `/api/media/<id>`; see `src/studio/media.ts`). `text` (`text` ≤ 12 characters, `style`: sharp-chrome / liquid-chrome / candy / foil / collage), `item` (`item`: a library id from `src/studio/library.ts`). Each has `transform` (position, rotation in degrees, uniform scale).
- `background.color`, optional `music` (`src`, `title`, `artist`), optional `view` (the post picture's camera from Frame your shot: `target`, unit `dir`, `dist`, picture `hfov`; IN3D matches its width of view, `In3DStage.setStartView`).
- **Units and axes:** 1 unit = the marker's width; +Y up out of the marker; origin at the marker's centre; +Z toward the marker's bottom edge, where the viewer stands.
- Defaults fill in missing fields, so editors can save minimal objects.
- Will grow in step 2: GIFs. Bump `version` on breaking changes.

`buildScene()` turns a scene into a three.js group, normalises model size and
grounding, wires videos as textures, and exposes `play()` / `pause()` /
`setMuted()`. **iOS rule:** the first `play()` must run synchronously inside
a tap; later calls work without one.

## AR pipeline (`src/ar/`)

User photos: copy `ImageBitmap`s into a canvas before using them as textures (three.js can't flip ImageBitmaps vertically, so they render upside down).

0. **Anti-jitter** (`smoothing.ts`, default on): a One Euro filter on MindAR's pose readings. Signed velocities (per axis, and the rotation as a vector, so wobble averages out) are themselves filtered at 1 Hz; the cut-off is 1.2 Hz + max(7 × speed in marker widths/s, 10 × turn speed in rad/s): still = strong smoothing, moving = little lag (~1.2° on a 30°/s turn). Render frames ease towards the filtered pose with 16 ms (hides 30 Hz reading steps); it snaps when the marker is (re)found. MindAR's own heavy filter ("steady") was rejected on the phone as laggy; the earlier size-based filter couldn't tell slow movement from wobble.
0a. **Gyroscope fusion** (`fusion.ts`, when `attitude` is given; `ArStage` passes the `GravitySensor`): `GravitySensor` turns each `deviceorientation` event into a camera-to-room quaternion (`cameraAttitude`: W3C Z-X'-Y'' angles, screen rotation) kept in an `AttitudeHistory` (1 s, interpolated, extrapolated ≤ 100 ms). `MarkerTracker` notes when MindAR reads each frame (wrapped `loadInput`); `PoseFusion.reading()` stores room = attitude(read time) × pose and smooths it with the One Euro `PoseSmoother`; `render()` draws view = attitude(t)⁻¹ × room, where t is the locked frame's read time (frame lock) or now. Gravity lock (`applyGravityLock`): the room frame has z up, so once the slowly averaged marker normal is within 25° of level (wall) or of up (table), with 35° to let go, each reading's normal is turned onto exactly level / up by the smallest rotation (position and the in-plane turn kept). MindAR's stale poses after a loss (`trackingStates[0].isTracking === false`) are ignored; the scene holds on the gyroscope for `COAST_MS` (600 ms). Without sensor data it falls back to the plain smoother. `gyroActive` / `GravitySensor.rate` feed the preview readout.
0b. **Frame lock** (`frameLock`, default on): MindAR's `inputLoader.loadInput` is wrapped so each frame it reads is also drawn into a back canvas; on MindAR's `processDone` the canvases swap, so the picture on screen is the frame whose pose was just applied (the live `<video>` stays underneath, read by MindAR and by the camera reflections). Both canvases get the video's cover-fit box in `resize()`. `trackFps` counts tracked frames per second.
1. `MarkerTracker.start()` opens the back camera (asking for 1280 × 720 unless `hd: false`; `?sd` in the address does that for comparisons; `window.__poseLog = []` collects raw poses for tests) (`getUserMedia`), creates MindAR's `Controller` (filters at MindAR defaults: `filterMinCF 0.001`, `filterBeta 1000`, warm-up/miss tolerance 5, `maxTrack 1`), loads the compiled `.mind` target, and matches the three.js camera to the phone camera (MindAR's own maths, ported).
2. Each pose update sets `anchor.matrix` (marker space: x right, y up the print, z out of the print, scaled so 1 unit = marker width). The scene sits in a `content` group inside the anchor.
3. `GravitySensor` reads `deviceorientation` (angles rather than acceleration: iOS and Android disagree on acceleration signs); `PlacementTracker` compares gravity with the marker's normal: flat below 35° of tilt, vertical above 50° (laptop screens leaning back count as vertical), current placement kept in between. Readings are ignored while the pose settles (300 ms after the marker is found) and when the marker is seen steeper than 55°; the rest are averaged (250 ms); the first decision is immediate, later changes must hold 700 ms. Unit tests in `src/ar/placement.test.ts`. `applyPlacement()` turns `content`: flat = 90° about X (the editor's floor on the print); vertical = upright with the editor's wall square (centre y 0.5, z -0.5) on the print, i.e. content at (0, -0.5, 0.5), so it looks exactly like the editor. Nodes with `userData.onMarker` (media "on the marker", authored on the wall square) are laid onto the print for flat markers (x, y → floor x, z = 0.5 - y, face up).
4. Shadows: a shadow-catcher plane on flat markers only; the shadow camera box is scaled by the marker width (shadow cameras don't inherit the anchor's scale).

## Markers

Two-step model (from the old prototype): the **QR code identifies** whose
marker it is; the **artwork is tracked**. The test marker is generated by
`scripts/make-test-marker.mjs` (seeded artwork + QR, compiled in headless
Chrome; its QR holds `…/m/test`, which the app maps to the test scene).
Quality gate: at least 250 matching points (test marker ≈ 4,100).
Design rules: [marker guide](../marker-guide.md).

**Personal markers (step 3):** one per account (D1 `markers`: code, seed,
version, ready, matching, attached post). The server picks a 7-character
code (no 0/o/1/l/i) and a seed; the phone draws the artwork
(`src/marker/artwork.ts`) with a QR code of `<site>/m/<code>`, compiles it
with MindAR's browser compiler (`src/marker/compile.ts`, at 768 px: ~3,500 matching points, ~1 s plus a few seconds of first-time TensorFlow.js warm-up; MindAR leaves one worker per compile) and uploads the PNG
then the .mind (R2 `markers/<code>-<version>.png|.mind`, public, cached for
good; a new design bumps the version). The .mind upload is refused under 250
matching points; the phone then redraws with a new seed. The artwork's base is the test marker's recipe (70 polygons in contrasting colours, 160 pen strokes, 500 dots/squares) in one of six palette themes, with a few stickers, squiggles and confetti on top and the QR card (white, 3-module quiet zone, error correction M) with @username and an "InRL" tag. Measured with the 45° fake camera, designs vary (6 of 8 strong); see STATUS. `npm run
marker-check` draws and compiles sample markers and checks their QR codes.

**Scanning:** `/m/:code` (what the phone's normal camera opens from the QR)
loads `GET /api/m/:code` (marker files, owner, the shown post with its scene,
the owner's posts) and tracks that one marker. `/scan` (Home's Scan button)
opens the camera without a marker (`ArStage.openCamera()` →
`MarkerTracker.openCamera()`), reads frames with `QrReader` (jsQR on a
downscaled copy, every 150 ms) until an InRL marker link shows up, then calls
`ArStage.track(mind)` in the same camera session. Home's tap calls
`primeGravity()` so iOS motion access is asked inside that tap.

## Hosting details

- `wrangler.jsonc`: `assets.directory ./dist`, `not_found_handling: single-page-application` (so `/ar` etc. load the app), `workers_dev: true`, `run_worker_first` for media paths (`/test/*.mp4`, `/test/*.m4a`, `/media/*`) and `/api/*` so `worker/index.ts` can answer `Range` requests with 206 and serve the API; `r2_buckets` (`MEDIA` → `inrl2-media`) and `d1_databases` (`DB` → `inrl2-media`) for cloud saving.
- Don't add a `_redirects` file: Cloudflare rejects a catch-all as an infinite loop; the SPA fallback already handles it.
- Build on Cloudflare: Node 24, `npm clean-install` (install scripts skipped by `.npmrc`), `npm run build`, `npx wrangler deploy`. Wrangler needs Node ≥ 22.
- Build results show as GitHub check runs ("Workers Builds: inrl2"); Cloudflare's logs are only in its dashboard, so ask Nico to paste them when a build fails.

## Known limits

- MindAR is little maintained upstream; we may need to maintain fixes ourselves.
- Marker-free AR on iPhone browsers isn't possible yet (Safari lacks WebXR AR).
- Large chunks: the AR page is ~1 MB (MindAR includes TensorFlow.js). Fine for now; revisit in step 7.

## 3D text and materials (`src/look/`, from the look test)

Built live in the browser, because the text and the photo are the user's.
These become the editor's 3D-text styles and material library in step 2.

- **Fonts** are pre-converted to three.js typeface JSON (`npm run look-fonts`), subset to typeable characters (~40 KB each). three's `TTFLoader` was avoided: it imports its font parser from a CDN at runtime.
- **Sharp chrome:** `ExtrudeGeometry` with a 4-step bevel. **Liquid chrome / balloon:** `inflate.ts` samples the outline, scatters interior points, triangulates them (Delaunator), and lifts each point by a circular profile of its distance to the edge; back side mirrored; outline normals forced horizontal to hide the seam.
- **Cut-outs (Designers collage):** `sticker.ts` draws artwork on a canvas (collage letter: pattern clipped to the glyph + ink keyline; or an emoji with a keyline), makes the alpha one solid piece (close hairline gaps, fill holes), traces its outline (marching squares, simplified and smoothed), fills behind the art inside the cut line with ink, extrudes it with a soft bevel, and prints the canvas on the front (custom UV generator; edge and back in `edgeColor`). Overlapping letters sit on alternating layers 5 cm·marker apart (more than their thickness) so they never intersect.
- **Bubblegum (`bubblegum.ts`):** per-letter inflated meshes laid out with the font's advances (hop + squash animation), sparkle sprites, `cloudShape()` (circles → mask → traced outline → inflated), `addFace()` (googly eyes and a smile placed on the front surface by ray-casting the mesh).
- **Materials:** chrome = `MeshPhysicalMaterial` metalness 1, roughness 0.07, iridescence 0.75 (thin film) for the oil-slick rims; glass = transparent physical material with reflections only (no `transmission`); balloon = vertex-colour gradient + clearcoat (foil: metalness 0.75); clay = satin + sheen + generated fingerprint normal map.
- **Reflections:** IN3D uses a per-world studio (gradient room with a bright horizon + soft boxes, PMREM). AR uses `CameraEnvironment`: every 400 ms the camera picture (and its mirror) is drawn into a 256×128 equirectangular canvas, brightened above / darkened below, then PMREM-filtered and set as `scene.environment`.
- Renderers use `NeutralToneMapping` for the look test.

## Cloud saving (`worker/cloud.ts`, step 2 piece 5)

- **Storage:** R2 bucket `inrl2-media` (binding `MEDIA`, keys `media/<id>`) for photos and videos; D1 database `inrl2-media` (binding `DB`) with tables `scenes` (id, owner, title, data JSON, thumb data URL, objects, created, updated) and `media` (id, owner, type, size, done, created). The worker creates the tables itself (`CREATE TABLE IF NOT EXISTS`), so no migrations or API token. **Never share a promise between requests** in the worker (only plain "done" flags): a request awaiting I/O started by another request hangs forever if that one is cancelled, as video range requests often are. `/api/media` is answered before any database work.
- **Owner = this phone** until accounts (step 3): the app makes a random 48-hex key (`localStorage` `inrl.owner`) and sends it as `X-InRL-Owner`; D1 stores only its SHA-256. Another key gets 403 on a scene or media upload it doesn't own.
- **API:** `GET /api/scenes` (list, no scene data; also removes media unused for over a day), `GET/PUT/DELETE /api/scenes/:id` (DELETE also removes media no other scene of the phone uses), `PUT /api/media/:id` (≤ 25 MB), `POST /api/media/:id/parts` → `PUT …/parts/:uploadId/:n` → `POST …/parts/:uploadId` (R2 multipart), `GET/HEAD /api/media/:id` (public, byte ranges for iPhone, cached for a year: a media id never changes content). Limits: scene JSON 64 KB, picture 200 KB, one file 160 MB, 3 GB per phone.
- **Development:** `vite.config.ts` runs the same handler with `worker/devCloud.ts` stand-ins (SQLite in WebAssembly via sql.js for D1, a folder for R2) in `.cache/dev-cloud/` (delete it to start over). Unit tests use the in-memory variants (`worker/cloud.test.ts`).

## Accounts (`worker/accounts.ts`, `src/account/account.ts`, step 3)

- **Passkeys only** (WebAuthn, no library): sign-up calls `navigator.credentials.create` (resident key, ES256 or RS256, attestation "none") and sends the browser's ready-made public key (`response.getPublicKey()`, SPKI) with the clientDataJSON and authenticatorData; sign-in calls `credentials.get` (discoverable, no user name typed) and the server checks the signature with WebCrypto (`worker/passkey.ts`: client data type/challenge/origin, rpId hash, user-present flag, DER → raw ECDSA signature, sign counter unless 0 as with iCloud Keychain). rpId = the page's host name, origin = the request's origin (the dev server passes the real Host so localhost:5173 works).
- **Challenges** are one-time rows in D1 (`challenges`, 5 minutes). Safari only shows the passkey sheet from a tap, so `Welcome` fetches a challenge when it opens (refreshed every 3.5 minutes) and the tap calls the passkey API first.
- **Phones**: D1 `phones` links a phone key's hash to an account. `whoIs()` (db.ts) resolves every request's `X-InRL-Owner` to the account's owner string `a:<account id>` when linked, else the phone hash. Signing up / in moves the phone's scenes and media (`UPDATE … SET owner`) and links it; signing out deletes the link, and the app forgets its scenes (all in the cloud first) and its key (`newPhoneKey()`).
- Tables: `accounts` (id = the passkey's user handle, unique username `^[a-z0-9][a-z0-9._]{1,18}[a-z0-9]$`, a few names reserved, name), `credentials` (id, account, public_key SPKI base64url, alg, sign_count).
- The account is cached in localStorage (`inrl.account`, `useAccount()`); `/me` re-checks it with `GET /api/me`.

## Publishing (`worker/publish.ts`, `src/account/publish.ts`, step 3)

- **Posts** (D1 `posts`: id, account, caption ≤ 150, data = the scene JSON copy, thumb, objects, created). `POST /api/posts` refuses scenes whose `media:` files aren't uploaded yet (409); the app first runs `syncScene()`. The thumb is a 600 px-wide picture the editor takes on → (`snapshot(600, 0.75)`, kept in sessionStorage `inrl.postpic.<id>`).
- **Media clean-up** counts posts: `usedMedia()` (db.ts) = media in the owner's scenes and posts; deleting a scene keeps media a post still uses; deleting a post leaves its media to the daily orphan clean-up.
- **What a marker shows**: its attached post (`markers.post`, set by "Attach to Your Marker" or Edit your Marker), else the newest post.

## InStudio editor (`src/studio/`, step 2)

- **Library** (`library.ts`): every item has `type` (object / character / sticker), `styles` (open list in `STYLES`; the three worlds are the first entries, an item can have several), `tags`, `materials`, `approved`. Builders return an object standing on y = 0, centred; idle animations through `update(t)`. 3D text styles live in `TEXT_STYLES` (the scene schema's enum must match; a unit test checks). New items are added at scale 1.5, text at 1.
- **Scene builder**: `buildScene()` handles `text` and `item` objects through the library, so AR, IN3D and the editor draw them identically.
- **EditorStage**: grey grid room tinted by the background colour, cyan workspace (marker square + back of the 1-high box), Streetwear studio reflections. One `SceneHandle` per object so edits rebuild only that object (`sync()` diffs by id and content). Camera: OrbitControls (one finger turn, pinch zoom, two-finger pan), our own double-tap reset. While an object is selected, every touch (anywhere) is an object gesture: OrbitControls is disabled for it in a capture-phase listener and its leftover damping is cleared (`stopViewMomentum`); with nothing selected, touches go to OrbitControls. Taps select (surface hits first, then the boxes around objects, so between letters / in a ring's hole counts; repeat taps cycle through overlaps). Object gestures: one finger drags it in the upright plane through it facing the camera (left/right, up/down); with two fingers, pinch = size (0.3–3×), twist = turn, both sliding up/down = push away / bring closer along the camera's level view direction (midpoint movement converted to marker widths at the object's distance ×2, 14 px dead zone). A drag over the selected object keeps it even if a spinning neighbour is in front; a quick tap picks the nearest. Positions are kept inside the area (`AREA`: x ±1, z from -0.45 to 1, height 0–1.5); while a finger drags past an edge the object rubber-bands (`stretchToArea`) and springs back on release, and the clamped position is what gets saved. The marker's 1 × 1 square is drawn on the back wall at z = -0.5, the rest of the area as a faint zone. Shadow cameras cover ±1.4 marker widths (editor, `addLights`, AR stage). Delete is immediate with a 5-second Undo. `setBottomInset()` slides the view up above an open sheet (camera view offset).
- **Selection outline** (`outline.ts`, editor only): the selected object's meshes are put on camera layer 5 and drawn white (override material, no depth test) into a 3/4-resolution mask; a full-screen pass samples 16 directions at two radii: just outside the silhouette = white line, further = teal glow. One extra mask render + one full-screen pass while something is selected. Picking also gives a 0.25 s ~5 % scale pop (ended before any gesture reads the scale).
- **Media** (`media.ts`, `screens.ts`, `placeMedia.ts`): picked files go to IndexedDB (`inrl` / `media`): photos redrawn to ≤ 1600 px (JPEG, PNG kept for transparency), videos kept as is (≤ 150 MB) with their size/duration. Scenes refer to them as `media:<id>`; `mediaUrl()` makes a blob URL (cached). Unreferenced files are removed when InStudio opens. Screens are offered by the picture's shape (`formatOf`, `SCREENS_FOR` in `placeMedia.ts`); device screens have their own ratio (`SCREEN_RATIO`) and the texture is cover-cropped to fill it (`coverCrop`). `mediaBody()` builds the screen types, the floating card and the print on the marker around the picture (unlit, no tone mapping). Media on the marker sit at `MARKER_Z` (just in front of the wall); in the editor they drag on the wall plane, twist about z, no lift, clamped to the square. Max 2 videos per scene; videos autoplay muted, `setSound()` unmutes from a tap.
- **GIFs**: the GIF sheet calls `/api/giphy?q=&offset=` (worker in production, the `inrl-giphy-dev` plugin in `vite.config.ts` in development: real GIPHY with `GIPHY_KEY` in the environment, test GIFs from `public/test` without). A picked GIF becomes a `video` with `gif: true`, `sound: false`, `src` = GIPHY's MP4 (CORS and byte ranges OK on media.giphy.com), up to 4 per scene.
- **Motions** (`motions.ts`): every object is built as `node` (placement, moved by the editor) → `moving` (motion) → the object. `applyMotion()` sets `moving` each frame for spin / float / bounce / pulse / sway / orbit, about the object's "up" (y, or z for prints on the marker), with a per-object phase from its id. The scene's `motion` field, else the library item's `motion`, else none. Changing it rebuilds the object; rebuilds keep the selection.
- **Undo / redo** (`Studio.tsx`): every scene change goes through `setScene(fn)`, which pushes the previous scene on a 50-step past stack and clears the future; undo/redo swap scenes between the stacks (the stage just re-syncs).
- **Snapping** (`gestures.ts`): `snapPosition` (x/z to the marker's centre line, y to the floor), `snapOnMarker`, `snapAngle` (15° steps within 4°), applied in `EditorStage` while dragging/twisting, with guide lines.
- **Tutorial** (`pages/StudioTutorial.tsx`, flag in `studio/tutorial.ts`): cards, then tips whose bubbles point at controls found by CSS selector.
- **My scenes** (`scenes.ts`, `pages/MyScenes.tsx`, `/studio`): every scene in `localStorage` (`inrl.scene.<id>`), an index (`inrl.scenes`: title, created, updated, object count, background, cloud state) and a 240×320 JPEG picture each (`inrl.thumb.<id>`, `EditorStage.snapshot()`: starting view, no selection, 3:4). Saved on every change; the pre-piece-5 single draft (`inrl.studio.draft`) is migrated as the first scene. Delete = card gone at once, 5 s Undo, then deleted on the phone and in the cloud.
- **Cloud saving** (`cloud.ts` → `worker/cloud.ts`): 2.5 s after editing pauses (and on leaving the editor) the scene's new photos/videos go to R2 (one request up to 20 MB, otherwise 20 MB parts, each retried twice), the phone's copy is then removed, and the scene + picture are PUT to D1. Cards show Saved / Saving… / On this phone. Offline or failed: retried on the next change, when My scenes opens, or on the `online` event. Pending deletes are kept in `inrl.scenes.deleted` and retried. Scenes only in the cloud (same phone key, phone copy gone) are listed and fetched when opened.
- **Preview** (`/studio/preview/:id`): the scene on the test marker, using the look test's `ArStage` (anti-jitter, flat/upright, camera reflections).

## Social layer (`worker/social.ts`, `src/social/`, step 5)

- **Tables** (created in `setUp`, db.ts): `follows` (follower, followee), `views` (post, viewer, day; one per person per day). Columns added later with `ALTER TABLE … ADD COLUMN` (errors ignored once they exist): `accounts.hidden` (test accounts), `posts.likes / views / comments` (counts kept on the post so lists stay quick), `posts.featured`, `posts.rank` (publishing time; recent likes will nudge it up).
- **Test accounts**: the app sends `X-InRL-Test: 1` when `localStorage['inrl.test'] = '1'` (set by the automated tests); sign-up stores `hidden = 1`. Hidden accounts' posts show only to other hidden accounts (so tests see each other) and by direct link.
- **Feed** `GET /api/feed?tab=foryou|following&offset=N`: 20 at a time (+ `more`), public. For You: `ORDER BY featured DESC, COALESCE(rank, created) DESC`; Following: joined with `follows`, newest first. Items carry the author and counts, never the picture itself (served at `/api/posts/:id/picture`).
- **Profiles and follows**: `GET /api/u/:username` (counts, bio, avatar, `me`, `followed`, posts newest first, `pinned` = the marker's post else the newest, the ready marker), `POST|DELETE /api/follows/:username`, `PUT|DELETE /api/me/avatar` (JPEG ≤ 400 KB → R2 `avatars/<account>-<random>.jpg`, served at `/api/avatars/<file>`, immutable; the old file is deleted), name + bio via `PATCH /api/me` (accounts.ts). `GET /api/posts/:id` now answers as the viewer (`owner.me`, `owner.followed`), so the app calls it with the phone key. Pages: `Profile.tsx` (`/me`, `/u/:username`), `components/EditProfile.tsx` (circle placement on a canvas → JPEG).
- **Likes and notifications**: table `likes` (post, account); `POST|DELETE /api/posts/:id/like` recounts `posts.likes` and sets `rank = created + min(likes, 24) × 2 h`; `GET /api/posts/:id` adds `liked`. `GET /api/notifications` builds the list from `likes` and `follows` (no table of its own); `accounts.notes_seen` + `GET /api/notifications/new` / `POST …/seen` drive the bell's dot (`useNotesDot`, polled each minute and on returning to the app). `In3DStage.onDoubleTap` / `onUserMove` let the post page turn double tap into a like and show Reset view.
- **Safety** (`worker/safety.ts`, route `safety`): tables `blocks` (blocker, blocked) and `reports`; `POST|DELETE /api/blocks/:username`, `GET /api/me/blocks`, `POST /api/reports`, admin `GET /api/admin/reports`, `POST /api/admin/reports/:id/done`, `POST /api/admin/remove`. Admins: `env.ADMINS` (wrangler `vars`; the dev server uses `process.env.ADMINS` or `nico`); `GET /api/me` adds `admin`. Blocks apply through `notBlocked(col)` / `blockedBetween()` (db.ts) in the feed, Discover, notifications, comments, profiles, posts, follows, likes. UI: `SafetyMenu`, `ReportSheet`, `pages/Admin.tsx`.
- **Discover** `GET /api/discover?q=&offset=` (social.ts `discover()`): no q = popular (featured, then `(likes×3 + comments×4 + views + 1) / (1 + age/7 days)`), paged by 20; with q = people (`username LIKE q%` or name contains, LIKE wildcards escaped) + scenes (caption contains), 20 / 40. Page `Discover.tsx`.
- **Comments** (`worker/comments.ts`, route `comments`): tables `comments` (id, post, account, text, created, hidden, likes) and `comment_likes`; `GET|POST /api/posts/:id/comments`, `DELETE /api/comments/:id`, `POST /api/comments/:id/hide|unhide`, `POST|DELETE /api/comments/:id/like`; `posts.comments` = visible count. Sheet: `components/CommentsSheet.tsx` (lifted above the keyboard with `visualViewport`). Notifications include comments.
- **Views** `POST /api/posts/:id/view` (phone key or account = the viewer), sent by the post viewer and by the marker page when a post is shown.
- **Post viewer** (`PostView.tsx`): loads `GET /api/posts/:id` (counts, the author's ready marker), keeps neighbours preloaded. Opens in IN3D: one `In3DStage(host, null)` per visit (no marker; `setBackground` = `studioGradient` from `scene/backdrop.ts`, `resetView()` frames the content's bounding sphere), each post swaps its scene in once its videos have a first frame (`firstFrames`), with a frozen frame of the old one (`freezeInto`) fading out over it; the post picture covers only the very first build. The strip is a scroll-snap carousel: the thumbnail nearest the middle (140 ms after scrolling stops) becomes the post. OrbitControls' default gestures. The `state.list` it was opened with (feed or profile: id, thumb, caption) becomes the bottom strip (swipe / tap → `/p/<id>`, replace). INRL navigates to `/p/<id>/inrl` with the same state. The strip is `components/PostStrip.tsx`, the post cache and `useStripList` (no list given → the author's posts) in `social/posts.ts` (shared with PostInrl), `firstFrames` in `scene/videoReady.ts`.
- **INRL on a surface** (`PostInrl.tsx`, step 6): in the test app, a `FloorStage` over the camera; one scene handle per post (neighbours kept, others freed), each swap drops the next scene into the same anchor at the same size with a pop. The strip list comes from router state or `?list=` (opened from Safari). Outside the app: a sheet with the app link (iPhone), the author's marker, Back to IN3D. **Markers in the same view:** the app sends QR texts (`__inrlNative.qr`, Vision); an InRL marker code → `/api/m/<code>` → `{type:'trackImage', id, url, width}` → ARKit image tracking → frames carry `image {id, m, w, tracked}`; `FloorStage.followMarker / leaveMarker` move the scene between the surface anchor and a marker frame (ARKit image frame × Rx(-90°) × width, then `applyPlacement` flat / vertical with hysteresis). The feed's Scan in the app opens this view (`state.scan`).
- **Frame your shot** (`EditorStage.setFraming`): hides the grid room and workspace, fog off, a gradient backdrop of the scene colour, auto-frames the objects' bounding sphere into the 4:5 picture (`pictureBox()`), object gestures off; `snapshot()` while framing keeps exactly that view (600 px, the post picture).
- **Feed page** keeps its list and scroll position for a minute (module cache), so going back from a post lands in the same place.
